### 關聯與排序

- 只有精確命中（名稱、代碼，或唯一股票名稱前綴）才依 `underlying_code` 查同標的期貨與權證，不以 `target_code` 猜標的。多檔歧義、非前綴子字串、缺名稱的代碼替代值都不任選。
- 台指／台股依實查的 `IX0001` 標的取三種規格，不依 root 名稱猜關係。「股票代碼＋選擇權」最多展開 4 個 root，維持多 root 交錯。
- 排序為現股或 ETF、連續期貨、權證、其餘結果。期貨以月份優先，每月依一般、小型、微型排列，缺規格略過；多 root 合併後統一排序；週別不擠掉月合約；已有連續代碼對應的實體合約不重複列出。「遠月」沿用既有 `R2`（次月）語意。

### 分段發布與請求層

- `product-search.ts` 只發布最終排序的穩定前綴；完整結果的 Promise 回傳順序不變。
- 靜態指數精確命中立即回傳；代碼直查成功不等待全股票目錄。
- 直接 Info 只共用執行中的請求，不保留完成結果、404、5xx 或逾時，避免拉長盤中資料的陳舊時間。
- `search-request.ts`：roots 與衍生合約的成功結果 LRU 各 16 項、TTL 60 秒，鍵含 API base 與台灣日期。執行中請求依鍵共用並計算讀者，LRU 淘汰不中止仍有讀者的請求，最後一位讀者退出才中止底層請求。目錄提早失敗時會釋放剩餘來源的本輪讀者。
- 搜尋 metadata 專用 4 路 FIFO：每位讀者可獨立取消，排隊中取消或到期就不再啟動。它只限制未取消的 client 端工作，不保證 daemon 端的同時工作數。
- 來源截止：股票來源 1000 ms，其他單一來源 1200 ms，皆含排隊時間；逾時或無讀者時以 `AbortSignal` 中止 metadata HTTP。分段查詢的總時間可能超過 1200 ms。
- 股票 Base／名稱來源分開快取與重試，依服務與台灣日期失效；世代檢查阻擋 A→B→A 的舊回應覆寫。typed 合約快取保留 code-only consumer 相容性，刷新失敗時保留最後有效合約。

### 消費端
