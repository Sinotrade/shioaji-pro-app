## 最終行為

| 項目 | 行為 |
| --- | --- |
| 實際成交與成交組 | 只畫 `Trade.status.deals` 的實際成交，標記錨定所屬 K 棒與成交價：買在成交價下方、賣在上方（預設三角形 ▲▼，尖端就是成交價）。同棒、同合約月份、同方向、同單位合組；單價組在該價，多價組在最低買價／最高賣價，區間線與刻度保留真實價位，價格標籤寫「均」與合計。 |
| 形狀、標籤與配色 | 設定面板（所有 K 線圖共用，點了就生效，沒有確定鈕）。形狀：三角形（預設）／箭頭／圓點／菱形，四種的版面與命中範圍相同；三角形與箭頭的尖端就是成交價，圓點與菱形沒有方向，賣畫空心（填標籤底色、描賣色），不看顏色也分得出買賣。標籤：不標／買賣／價格（預設）；原本的「三角形」樣式改叫「不標」。標籤是半透明玻璃底。顏色：「買 ■ ▾」「賣 ■ ▾」各自展開 10 色色盤（同畫圖工具）＋「預設色」，存在 `sj-pro-chart-fill-buy`／`sj-pro-chart-fill-sell`（空字串＝預設藍買橘賣）；勾「跟 K 棒同色」改用漲跌色，勾著時換色會自動取消。 |
| 圖例列與指標對話框 | 圖表左上角圖例列（同技術指標）一列「成交 ▲買 ▼賣 N 筆 [眼睛][齒輪][×]」，示意字元跟著形狀換，N 和「明細 N」相同。點「成交」或齒輪開／關設定面板（畫圖工具同款彈出層，Esc 或點外面關閉）；打開時焦點移到目前的形狀鈕，Esc 關閉後回到打開它的鈕。眼睛暫時隱藏：只剩「成交」（轉灰）與三顆鈕，圖上不畫、沒有提示框、工具列沒有「明細」。× 從這張圖移除（圖例列消失），從「指標」對話框加回。隱藏中或已移除時打開設定會先恢復顯示。三顆鈕一直顯示，點擊範圍約 21×21。「指標」對話框最上面「內建」區有「成交標記」一列（色塊、已加入、移除），點它打開設定面板，未加入就先加回。權證、指數、組合的圖沒有圖例列，也沒有這一列。 |
| 工具列與設定 | 工具列只留「明細 N」（含無對應 K 棒的成交），沒有「成交」開關。每張圖的狀態存在版面 `Block.chartFills`：缺省＝顯示、`false`＝隱藏、`'off'`＝已移除；舊版存的 `false` 現在顯示成隱藏（圖例列在、轉灰）。彈出視窗不帶這個狀態，隱藏、移除的圖彈出去會重新顯示（既有行為）。「圖表下單設定」沒有「成交標記」分頁，`chart-order-popover` 回到官方 v0.1.57。帳戶範圍在設定面板最下面一行：「帳戶：{這張圖的帳戶，套隱私遮罩}　改成全部帳戶」或「帳戶：全部帳戶　改成目前帳戶」。 |
| 交易安全 | 操作圖例列（成交、眼睛、齒輪、×）、設定面板內的控制、「明細」，以及「指標」對話框裡成交標記那一列（打開、移除）前，先解除點價武裝；開關「圖表下單設定」照舊保留武裝。圖例列在圖表區裡，標成浮動層（`data-drawing-overlay`），按在上面不會被委託線拖曳或畫圖工具接走。設定面板的 Esc 只關面板，不算進 Esc×2 全部刪單。 |
| 提示框 | 最多列 4 筆，顯示整棒筆數、合計及多價位均價摘要；滑到的價位先列。跨合約或全部帳戶時，合約／帳戶放每筆第二列，寬窄框一致。窄框（圖表區小於 380px）時間只到秒、放不下時換行；寬框與清單到毫秒。 |
| 明細清單 | 只列最新 500 筆，其中保留 50 個名額給無對應 K 棒的成交，顯示較早未列筆數；換月日多「合約」欄。清單可鍵盤聚焦、內部捲動。 |
| 這根 K 棒 | 滑過有成交的 K 棒、提示框出現後，再按「明細」，清單捲到那根、標亮那幾列，頂端一行摘要，旁邊「×」可取消。不設時間限制，但用一次就忘，關掉再開不會再出現；換商品、週期、帳戶、環境、隱藏或移除成交標記，或已確認時那根已經沒有成交，都會取消清單上的標示。 |
| 此棒摘要與上限 | 單一價位也顯示價格，如 `▲ 買 3 口 · 12,345`；多價位和提示框同格式，如 `▲ 買 22 口 · 均 12,345.6 · 12,340～12,350`。超出 500 列時寫「此棒成交未列於目前清單」或「此棒另有 N 筆未列於目前清單」，不突破上限；打開時不搬鍵盤焦點，新回報不再捲動。 |
| 全部帳戶 | 同市場所有可交易帳戶合併顯示，不同帳戶可合成同組，明細逐筆列帳戶並套隱私遮罩；不收其他市場帳戶。 |
| 資料來源閘門 | `fillsReady` 預設未確認；須目前環境的委託經權威查詢確認、沒有待對帳、串流即時且成交數量與明細一致。工具列與明細說明待對帳原因；未確認不畫新資料，上次確認標記可淡色保留、不可滑過且不列舊明細。範圍改變或主視窗鏡像失效即清掉。 |
| 時間對齊 | N 分 K／日 K 由 1 分 label 聚合；收盤寬限內定盤併入該時段最後一根。即時 K 棒按原始 tick 時間分桶，成交先找歷史桶再找即時桶。連續月換月日以近月最後交易日 13:30 分界，之前收前月、之後收目前月份。 |
| 正式環境 wire | 期權委託回報可能為 `exchange: 'TIM'`、`target_code: null`、`code: full_code`；期權不比交易所，股票仍比對。委託 wire 有真實去識別 fixture，Deal payload 的正式樣本仍缺。 |
| 請求數 | 和基底相同，只多一次換月合約查詢（當日委託有換月相關合約時才查）。 |
| 效能機制 | 每張委託投影快取沿用不變的成交，也沿用內容相同的鏡像；明細檢查與投影共用範圍篩選，同棒換價位沿用摘要。大量時合併連續回報；隱藏或移除標記時明細檢查與合併計時器零成本，釋放投影快取及保留組的逐筆成交。窄於 3px 時，多價組的各價位座標只取兩端。 |

## 重現方式（示範頁）

示範頁目錄：`scripts/chart-fills-demo/`。啟動：

```sh
pnpm exec vite --config scripts/chart-fills-demo/vite.config.ts --port 5298
```

網址：`http://127.0.0.1:5298/`；壓力測試例：`/?stress=20000&live=20&quote=10`。

| 參數 | 範圍與作用 |
| --- | --- |
| `stress=N` | 0–200000，產生 N 筆示範帳戶 A 的成交 |
| `live=R` | 0–200，每秒在最新一根追加 R 筆 |
| `quote=Q` | 0–200，每秒 Q 次合成報價 |
| `mirror=1` | 每秒把整份委託換成內容相同的複本，模擬彈出視窗的鏡像 |

`live`、`quote`、`mirror` 只在有 `stress` 時有效。壓力模式的全域函式（只在有 `stress` 時存在）：`window.__stressStop()`：停止回報、報價與鏡像。`window.__stressStats()`：回傳 `{ fills, quotes, total }`。
控制列：商品、主帳戶、深色／淺色、標籤（不標／買賣／價格）、顯示帳戶（目前帳戶／全部帳戶）、密集成交、待確認、新增一筆示範成交。形狀與顏色沒有在控制列，從圖上圖例列的「成交」打開設定面板換。

| 情境 | 操作與觀察 |
| --- | --- |
| 多價位組 | 開「密集成交」，觀察區間、均價標籤與提示框摘要 |
| 淡色保留 | 按「待確認」，觀察舊標記淡色保留及待確認說明 |
| 帳戶隔離 | 切主帳戶或按「新增一筆示範成交」，切回商品與帳戶核對 |
| 這根 K 棒 | 滑過有成交的 K 棒、提示框出現後再按「明細」，觀察摘要、標亮與「×」 |
| 設定面板與圖例列 | 點圖例列「成交」或齒輪，換形狀、標籤、顏色；按眼睛隱藏、按 × 移除後從「指標」對話框「內建」加回 |

`quote` 會把今天最後一根對齊現在時間，並丟掉晚於現在的 K 棒。13:30 前跑時，今天晚於現在的壓力成交（09:00 前是今天全部）會當成等待新 K 棒，既不畫也不列在明細，「明細 N」會少於 `stress`；要互相比較的量測請在 13:30 後跑。
換月日示範頁做不出來，只有單元測試涵蓋。

### 送出前總檢（2026-11-17 審查、11-19 修正、11-20 驗收）

PR 內文逐句對照程式碼，並從交易安全、正確性與狀態、介面與無障礙、精簡與測試四個角度審查 11-17 改版；每項發現再由獨立的反方從「能否重現」「是否刻意」「影響」三方面複查，至少兩方推翻不了才算成立。修正：

- 武裝點價時按成交圖例列：按下就解除武裝、提示收起，圖例列排在提示後面時整欄上移，第一下落空、再按會按到移上來的委託列 CANCEL（不經確認刪單）或觸價 ×。圖例列改排在提示之前。
- 從「指標」點「成交標記」會當場拿掉全視窗遮罩，雙擊的第二下可能穿到底下的閃電下單或刪單鈕。拿掉遮罩後放一層透明遮罩 0.5 秒，並在 window 攔下這段時間的指標事件（剛打開的設定面板不會被當成點外面而關掉）。
- 設定面板的內側焦點框只留給分段鈕；色盤色塊改用瀏覽器預設焦點框（原本跟色塊同色，看不到）。
- 已移除後從「指標」加回並打開設定，按 Esc 關閉時焦點掉到 body；改為打開時焦點不在任何元素上，就還給圖例列的「成交」。

三項行為修正各有一個測試，改前會失敗、改後通過。示範頁無頭 Chromium 實測：武裝中真的點一下眼睛就隱藏；雙擊「成交標記」列後設定面板仍開著、遮罩 0.5 秒後消失；色塊與分段鈕的焦點框分別是瀏覽器預設與內側 2px；加回後 Esc，焦點回到「成交」。

2026-11-20 獨立驗收（另一個模型，唯讀）：四項修正在示範頁都重現得出來，換回 11-17 的寫法就重現原本的問題；三個新測試在 11-17 的程式上剛好失敗。另外找到並修正：

- 遮罩測試只驗 listener 有註冊，攔截函式改成什麼都不做也會通過。測試改成直接呼叫攔截函式，驗證滑鼠點擊被停住、計時器有清掉。
- 0.5 秒內用鍵盤按面板裡的按鈕也被吞掉：`detail` 0 的 click（鍵盤或程式觸發；滑鼠、觸控、筆至少是 1）不是雙擊，改為放行。只放行 click，因為 Chromium 的 pointerdown 也是 `detail` 0。
- 雙擊的第二下按在遮罩上，焦點從面板掉到 body：攔下 mousedown 時一併擋掉預設的焦點移動。
- 焦點歸還的測試改成把 Esc 交給 `useEscClose` 註冊在 window 的 keydown listener（跟真的按鍵同一條路），並驗證這一下不算進 Esc×2；測試裡的 spy 在每個測試後還原。

變異測試：攔截函式不攔、不清計時器、鍵盤 click 也攔、mousedown 不擋預設、不分事件種類放行 `detail` 0，五種改法都會讓遮罩測試失敗。示範頁重跑：雙擊（間隔 0、120、300 ms）後底下收不到點擊、焦點留在面板；0.5 秒內用鍵盤換形狀有效；Esc 後焦點回到「成交」。無頭 Chromium 與 Playwright 內建的 WebKit 26.5 都通過；桌面 App 的 WKWebView 未驗證。

同日另修：雙擊圖例列的 ×。整列移除後下面的委託列移到游標下，第二下會按到 CANCEL（不經確認刪單）。示範頁加一筆假掛單實測（刪單點擊在 document 攔下、不執行），無頭 Chromium，4 種委託文字長度 × 顯示／隱藏 × 雙擊間隔 0／120 ms 共 16 種：改前 4 種按到 CANCEL（隱藏中「委買1 @183」、顯示中「委買1000 @1,234.5」各 2 種），改後 0 種。改法：× 也放同一層 0.5 秒遮罩；眼睛只換內容、整列還在，不放。測試驗證 ×（顯示與隱藏中）會放遮罩、眼睛不放；拿掉這行測試就失敗。

獨立驗收（另一個模型）改挑兩個引擎都會重疊的委託文字（隱藏中「委買1 @1,005」、顯示中「委買1000 @1,234.5」），試 0.5 秒內的 6 種按法（雙擊間隔 0／120／300／450 ms、兩種長按）：無頭 Chromium 與 Playwright WebKit 改前各 12/12 按到 CANCEL，改後 0/12，第二下的 click 在 window 就停在遮罩。第二下按住超過 0.5 秒才放開，不會產生 click。0.5 秒是硬上限：600 ms 才按第二下照樣按得到，雙擊速度調得很慢的人仍可能碰到。

驗收另外找到：在「指標」對話框雙擊「移除」，會剛移除又加回，還打開設定面板。開設定那層遮罩擋住了 CANCEL，所以碰不到。改法：「移除」也放遮罩。兩個引擎改後第二下都停在遮罩、對話框還開著；拿掉這行測試就失敗。

官方指標圖例列的 × 是同樣的寫法。加一條指標和一筆假掛單，雙擊指標列的 ×：4 種委託文字在 Chromium 都按到 CANCEL。這段是官方程式碼，不在本 PR 範圍。
