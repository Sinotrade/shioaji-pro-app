fix(search): 修正櫃買指數名稱搜尋缺漏，並整理搜尋結構、效率與相關商品、ETF 顯示

## 變更內容 / Summary

這個 PR 原本只是要修正「櫃買指數」用名稱搜尋不到的問題。修正後，再延伸整理以下幾件事：

- 名稱搜尋的資料來源與請求結構。
- 搜尋時的重複運算。
- 讓名稱或代碼都能列出同標的相關商品與 ETF。

介面樣式與窄視窗調整，是後續使用需求與驗收時提出的延伸項目，與報價連線無關。

### 問題與原因

- **名稱與代碼結果不一致**：輸入「櫃買」只會找到櫃買期貨，輸入「櫃買指數」是空清單。但輸入完整代碼 `IX0043` 可以找到，表示 API 有這個商品，問題出在名稱搜尋。
- **原因**：名稱搜尋用的是一份寫死的指數清單，只有 `IX0001`（加權）與上市類股指數，漏了 `IX0043`，交易所也一律標為 `TSE`。完整代碼走直接查合約的路徑，不經過這份清單，所以兩種輸入結果不同。
- **延伸檢查發現的問題**：
  - 台積電／2330 等查詢，無法一致列出同標的期貨與權證。
  - 券商批次目錄的名稱覆蓋不完整。
  - 內建 ETF 名稱快照不會反映新上市或更名。
- **補齊名稱後 CPU 上升**：同一批 3155 檔商品的別名由 635 筆增為 2984 筆。原本每次輸入都會：
  - 重複正規化代碼、名稱與每個別名；
  - 為別名配置新陣列；
  - 排序時再算一次代碼。

  因此搜尋 CPU 明顯上升。

### Before / After

| 輸入 | Before | After |
| --- | --- | --- |
| 櫃買指數 | 空清單 | 找到 `IX0043`，交易所為 OTC |
| 櫃買 | 只有櫃買期貨 | 櫃買指數與櫃買期貨都會列出 |
| 台積電／2330 | 只有現股 | 現股、期貨近次月與權證依序列出 |
| 00981 | 可能先列 009810、009811 | 00981A／B／D／T 等同系列 ETF 優先 |

### 修改

- **櫃買指數**：
  - 補上 `IX0043` 的名稱與別名，交易所改為逐筆標示。
  - 名稱候選必須與券商目前有效的指數合約交集才會顯示。這不是另建一份可交易清單，也不會每次輸入都逐檔抓取指數資訊。
  - 指數仍不可下單。
- **自選列重繪**：修正拖放 callback 參照不穩、導致自選列 memo 失效的問題。搜尋造成的整份自選重繪因此減少，行情也不會被清空。
- **窄視窗工作區**：
  - 改為直向顯示並停用拖放縮放，不覆寫桌面版面。
  - 修正快速縮放與手勢造成的欄位密度錯誤回寫。

### 最佳化

- **搜尋分層**：商品身分、名稱來源、關聯排序、請求共享與取消、UI 呈現各自負責。
  - 商品是否存在，以及類型、交易所、代碼，一律以券商有效合約為準。
  - 官方名稱來源只補現有商品的名稱與別名，不會產生券商尚未支援的商品。
- **減少重複請求**：
  - 目錄與查詢共享資料，請求採有界佇列，並可取消。
  - 名稱來源改為背景批次刷新，搜尋不必等待外網；刷新失敗時沿用最後一份有效資料。
  - 換關鍵字不會重抓整份名稱或合約。
- **結果穩定**：
  - 分段回傳的結果依既定順序補齊，權證先回來也不會排到期貨前面。
  - 輸入變更、關閉或商品異動後，晚到的舊回應不會覆蓋新查詢。
- **搜尋計分 CPU**：保留完整目錄、名稱、別名、分數、排序與回傳原物件，只減少重複工作。
  - 只由大寫英文、數字與基本漢字（不含「臺」）組成的字串，正規化後必定不變，因此直接沿用原字串。其他字串仍走原本的去空白、NFKC、臺轉台與轉大寫流程。
  - 別名改為單次走訪比對，不建立新陣列。代碼或名稱已精確命中時，不再掃描其餘別名。
  - 排序時重用已算好的正規化代碼。
  - 不使用文字或查詢快取，因此不增加失效與淘汰的維護責任。
- **相關商品**：用名稱或股票代碼都能列出同標的商品。
  - 台積電依序為：現股 → 一般近月 → 小型近月 → 一般次月 → 小型次月 → 權證。
  - 台指先列一般、小型、微型近月，再以同樣順序列次月。
  - 缺少的規格會略過。同一商品的連續合約與對應實體月份合約只列一次，不混入不同規格。
- **ETF 排序**：
  - 輸入 `00981` 時，已確認為 ETF、數字前綴相同的字母尾碼代號（00981A／B／D／T）排在同樣有效的 009810、009811 之前。
  - 完整輸入 `009810` 時，仍以精確代碼優先。
  - 字母尾碼只用於系列排序，不用來判斷是否為主動式 ETF。

### 新增

- **名稱與別名來源**：新增官方 ETF 與上市、上櫃、興櫃一般股的名稱與別名來源。結果仍須符合券商目前的代碼與市場。
- **單筆合約名稱補查**：輸入精確股票代碼並帶有選擇權意圖、但目錄缺少名稱時，只對唯一有效的股票補查單筆合約名稱。不會逐檔抓取，不寫入報價，也不修改原合約。
- **搜尋介面**：
  - 各商品類型加上文字分類與淡色標籤，顏色跟隨自訂主題。
  - 毛玻璃效果只套用在背景，文字不降低透明度。
  - 所有寬度都是單行顯示，代號在前、名稱在後。窄版只在視覺上先收起類別與補充資訊。
  - 目前選取的列可展開完整資訊。在完整資訊區塊操作鍵盤，不會觸發全域交易快捷鍵。

## 驗證 / Test plan

以下為本機紀錄，並經獨立複核，並非雲端 CI 結果。本次更新相對前一版，只改動搜尋計分模組（`stock-index.ts`）與其測試，並新增搜尋與報價串流交錯的回歸測試。

### 自動測試與建置

- **完整 Vitest**：264 個測試檔中 263 個通過、1 個略過。4238 passed、0 failed，另有 2 項既有 native 測試 skipped。
- **Node ETF 產生器**：10 passed。
- **建置與檢查**：`tsc -b`、`vite build`、`git diff --check` 通過。
- **搜尋計分測試**：
  - 快速路徑與原正規化流程逐字對照。
  - 排序、同分順序與回傳原物件不變。
  - 其中「不呼叫正規化」一類的斷言屬於效能守門。這類斷言失敗代表效能回歸，不代表功能錯誤。
- **報價交錯回歸**：
  - 正式的報價、串流與 store 程式碼完全未改。
  - 新測試使用真實 follower 與 store，但所有 IO 都 mock 或禁止。
  - STK 與 FOP 各以 120 筆 Tick 與 121 筆 BidAsk 與搜尋交錯，並以 fake timer 逐步推進。
  - 確認逐筆資料完整，只有 React 通知被合併。
  - 這是合成的正確性測試，不代表真實行情或負載延遲。

### 手動核對

- **dev**：
  - 自選與命令面板兩個搜尋入口：`2330`、`00981`、`櫃買指數`。
  - 另核對：台積電／臺積電、台指、`009810`、`IX0043`。
- **build**：命令面板的 `2330`、台指、`00981`、`櫃買指數` 結果順序與 dev 相同。
- **UI**：本次未改 UI／CSS。320／360 px 窄版與毛玻璃效果沿用前一版的核對結果，本輪未逐尺寸重測。
- **SSE**：週日觀察 35 秒，收到 2 次 heartbeat，沒有 Tick／BidAsk。這只表示傳輸存活，不代表夜盤報價已通過。LIVE 狀態或 heartbeat 也不等於價格新鮮。
- **未操作項目**：未實際下單，未寫入自選成員或訂閱，未登入，未複製憑證，也未重啟既有服務。

### 效能量測

- **條件**：
  - Node 24.11.1，同一 process，同一 module-local 封裝。
  - 3155 檔相同商品與完整名稱。
  - 10 個查詢各跑三輪，每輪取各查詢的 p95 後平均。
- **比較對象**：「優化前」指名稱已補齊、但尚未做本次 CPU 修改的版本。下表數值為 10 個查詢的範圍。

| 情境 | 優化前 p95 | 優化後 p95 | 降幅 |
| --- | --- | --- | --- |
| 暖搜尋 | 1.4288～1.7391 ms | 0.4296～0.5136 ms | 67.62%～71.39% |
| 新目錄第一次查詢 | 1.3990～1.6831 ms | 0.4269～0.5864 ms | 64.04%～69.48% |

- **相對最初名稱較少的舊版**：暖搜尋快 47.69%～52.30%，第一次查詢快 41.79%～49.79%。
- **門檻**：每個查詢都個別通過 5% 回歸門檻，沒有用總平均掩蓋個別查詢。
- **原始樣本**：暖搜尋 30000 筆、第一次查詢 12000 筆，全數保留。量測方法與校正過程詳見 QA 紀錄。
- **涵蓋範圍**：只量 `searchStocks` 的過濾、計分與排序 CPU。「第一次查詢」指換新目錄後的第一次查詢，不是 App 冷啟動。
- **未涵蓋**：
  - 瀏覽器／WebView、React、IME 與 JS 或 App 啟動。
  - 目錄建構成本與記憶體。
  - `searchProducts` 包裝層。
  - 報價延遲與端到端 SLA。
  - 整個 PR 的整體 CPU。
