# Gemini 商品搜尋獨立驗證考題

網頁第二版受測版本為 `bba36467c7459bc297be9a1d2b1ea6a5c7383983`，比較基準為 `be4cbd3073df2625db0d51f767c812a27f79cb8e`。目標是找出搜尋與商品身分處理的錯誤，以及現有測試無法證明的範圍，不是替既有實作背書。原 CLI 第一版因認證失敗，沒有模型答案。

## 作答規則

第一輪只提供需求與附行號的正式程式，不提供既有測試、PR 草稿或上輪驗收結論。你沒有執行工具，必須把推論標為「靜態分析」，不能宣稱已執行測試、操作 UI 或接收到報價。

每個發現必須附檔名、行號、前置條件、輸入／事件順序、預期與實際差異、最小重現測試及嚴重度。區分本次新增回歸、既有缺陷、產品範圍限制與待查證假設。提出至少 8 個應該讓錯誤實作失敗的反例，並說明哪種錯誤變更會被測試抓到。

不得讀取或索取金鑰、帳戶／持倉資料，不得下單、改帳戶、寫伺服器自選清單、重啟服務、修改正式程式、push 或建立 PR。若資料不足，明列缺少的證據，不捏造 API 回應或通過結果。所有額外商品資料只能由主驗收者對隔離的 21323 做有限量唯讀查核。

## 作答格式

請輸出完整 JSON 物件，勿包 Markdown code fence：

- `summary`：一句話結論與最重要的阻擋風險。
- `answers`：12 題各包含 id、靜態判斷、證據、待執行查核。
- `findings`：id、severity（P0 至 P3）、classification、file、line、root_cause、reproduction、expected、observed_from_code、suggested_fix、confidence。
- `test_cases`：至少 8 個獨立反例，各附最小 fixture、事件順序、斷言及應抓到的 mutation。fixture 必須標為 synthetic，不當成真實 API 證據。
- `test_code`：最值得新增的 Vitest 測試程式，可用字串提供；只提出，不宣稱已執行。
- `unverified`：缺證據或工具而無法判定的項目。
- `verdict`：`BLOCKED_BY_CONFIRMED_STATIC_BUG`、`NEEDS_EXECUTION` 或 `NO_STATIC_BLOCKER`，不得將後兩者描述成可發布。

## 主驗收者評分與複核

不採用 Gemini 自評作為合併依據。每題的配分衡量證據覆蓋，不代表可發布程度。P0／P1 需可重現且不得未處理；P2 需明確修正或記錄處置。只有文字敘述、沒有反例或原始碼定位，不給「驗證通過」。

主驗收者會保存 Gemini 原始輸出、實際模型名稱、CLI 版本、受測 SHA、題包雜湊、執行時間及工具使用統計。模型說法由本機實測逐項判定為 CONFIRMED、REJECTED 或 UNVERIFIED，並另列未驗收的原生／行情範圍。
