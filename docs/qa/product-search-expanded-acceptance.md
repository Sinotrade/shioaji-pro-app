### 原因與工程修正

商品身分同樣是 3155 筆，但官方名稱補齊後，別名由 635 筆增加至 2984 筆，只有代碼、沒有名稱的項目由 1983 筆降至 450 筆。原本每次輸入都對每列的代碼、名稱、別名完整執行 trim／NFKC／臺轉台／大寫，另外建立別名陣列；ETF 比較器還會重複正規化代碼。新增名稱的功能成本因而被重複放大。正規化呼叫數是工作量證據，不等於全部 CPU 成本的占比。

本次修正：

1. 只對確定經原正規化鏈仍完全不變的字元，直接使用原字串：ASCII 大寫、數字及 U+4E00 至 U+9FFF 基本漢字，排除「臺」。其他字元完整走原鏈，不擴大 Unicode 假設。
2. 別名改成單次惰性比對，不配置正規化後的別名陣列。主代碼或主名稱已精確命中時，不重做不能影響分數的別名工作；別名只命中片段時仍繼續找精確命中。
3. 同列相同字串與排序器重用當次已得到的結果。保留原始名稱長度計分、同分穩定性、ETF 字母尾碼／交易所次序，以及回傳原物件參照。

## 資料責任與維護邊界

| 層級 | 唯一責任 |

| `product-search.ts`、`search-request.ts` | 關聯、排序、分段結果及有界共享讀者生命週期；不是另一份名稱資料庫 |
| 共用搜尋元件／grid adapter | 呈現、焦點／快捷鍵邊界、浮層定位及幾何世代，不擁有報價或名稱來源 |

ETF 名稱沿用三個官方來源的整批原子驗證；普通股票使用 TSE／OTC／OES 三個固定來源，逐來源保留最後好資料，再以單次批次版本發布。普通股票限定非 0 開頭的四碼，不覆蓋 ETF。日期倒退、無效日期、衝突代碼及超過 10% 縮水不接受；保留原顯示名稱，只在搜尋比對時正規化。

成功後 5 分鐘內重用，失敗後 30 秒才重試，台灣跨日於下一次觸發時刷新；沒有定時輪詢或逐字網路請求。公開刷新不阻塞搜尋。正式網頁 host 必須另行部署相同固定路由，dev proxy 通過不代表正式 host 已部署。

公開 client 只接受六條相對路由，省略 credentials、不跟隨 redirect，限制 5 秒總截止及解碼後 2 MiB。loopback dev／preview proxy 再核對 Host、method、空 body／query，固定上游只帶 Accept；3 秒總截止、同樣 body 上限、拒絕含 Set-Cookie 的回應。取消／晚到回應的 reader 會釋放，不等待無回應的 cancel promise。

dev／preview 必須使用 `http://127.0.0.1:埠號/`。使用 `localhost` 的 Host 不在白名單，公開名稱路由會回 403；不為方便而放寬防 DNS rebinding 的檢查。

原生公開名稱傳輸尚未證明 cookie 隔離，因此維持零請求、零刷新 timer，畫面明示「原生版官方名稱更新未啟用，使用券商與內建名稱」。不把 browser credentials 設定當成原生 cookie 管線證明。

### 驗收發現並修正的具體問題
