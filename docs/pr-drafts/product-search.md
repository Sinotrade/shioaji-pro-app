修正櫃買指數中文搜尋、補齊 ETF 名稱，並讓股票／ETF 名稱及代碼分段列出同標的期貨與權證，維持原定排序。本機功能驗收通過；指定的 Claude Opus 5.5 ultracode 審查仍待重新登入。未推送、未建立 GitHub PR，也未合併或發布。

## PR 資訊

- Base：官方 `main`，`be4cbd3073df2625db0d51f767c812a27f79cb8e`。
- 本機分支：`codex/product-search-related`，不堆疊報價欄 PR。

- 原始問題：[how0531/1017 問題說明](https://github.com/how0531/1017/blob/8b99a29/docs/issue-otc-index-search.md)。

## 原因

1. 指數名稱搜尋只用 27 筆寫死的清單，漏掉 `IX0043`，且每筆交易所皆寫成 `TSE`。直接代碼查詢走另一條路，所以輸入 `IX0043` 找得到，中文名稱卻找不到。
2. 同標的商品只在特定類型關鍵字出現時查詢；兩個搜尋入口未開啟權證。模糊搜尋的第一筆股票還會被當作精確標的，造成錯誤關聯。
3. 來源共用失敗鏈、結果直接截斷，以及輸入變更後保留舊建議，分別造成可用結果被連坐、現股被衍生商品擠掉與選錯上一輪商品的風險。
4. ETF 名稱借自權證標的，覆蓋不足；基金基本表也不保證已同步更名。實測 0053 在基金表仍為「元大電子」，每日成交與 broker Info 已改為「元大科技市值」。
5. 補充反例確認中文組字 Enter、名稱來源失敗永久降級、跨服務與同碼異型別快取，以及無關來源卡住搜尋的缺口。

## 修改內容

- 新增帶交易所的指數搜尋資料，共 38 筆。保留既有上市類股，加入實查的櫃買指數、7 筆櫃買類股、未含金融／電子指數及 `TAIWANVIX`。不將這份清單描述成完整指數目錄。
- 加入 390 筆官方 ETF 名稱快照，以當前 broker `exchange + code` 取交集。實查可對應 359 檔（TSE 241、OTC 118）；名稱支援簡稱、已收錄的完整名稱、新舊名、全形及純文字 entity 解碼，並標示 ETF。沒有將 ETF 改為新的合約型別，也不憑基金持股推導關聯。
- 產生器批次讀取 TWSE 基金表、TWSE 每日名稱與 TPEx ETF 名單；僅開發更新時使用，搜尋執行期不外抓、不逐檔讀 Info。來源異常不覆寫既有快照。詳見 [ETF 更新交接](../qa/etf-search-catalog.md)。
- 「台積電／臺積電／2330」精確命中現股時，依 `underlying_code` 查同標的期貨與權證，不以 `target_code` 猜標的。
- 名稱／代碼搜尋採「現股或 ETF → 同標的連續期貨 → 權證」，不再讓權證穿插期貨。期貨月份優先，每月依一般、小型、微型排列，即「一般近月 → 小型近月 → 微型近月 → 一般次月 → 小型次月 → 微型次月」，缺規格略過。多根來源合併後統一排序，保留完整合約。週別不擠掉這六筆月合約；額外實體月份在權證後，已有連續代碼對應的實體合約不重複列出。
- 「台積」只有唯一股票名稱前綴時，才關聯到台積電；多檔歧義、非前綴子字串或只有代碼的缺名稱替代值，不任選標的。台指／台股按實查 `IX0001` 標的取得三種規格，不依根商品名稱猜關係。「2330 選擇權」能搜尋 `CDA/CDO`，最多展開 4 個根商品，仍維持多 root 交錯。
- 權證同時檢查到期日與最後交易日；日期不足標示「交易日期待確認」，不宣稱可交易。
- 先發布主商品，再發布已排序的連續期貨，最後補權證及其餘結果；只發布最終排序的穩定前綴。權證先回也不會插到仍在載入的期貨之前，完整 Promise 回傳順序保持不變。
- `2330` 與台積／台積電、`00679B` 與元大美債20年，皆列出相同關聯商品。成功直查仍略過全股票目錄；直接 Info 僅共用執行中的請求，不保留完成結果、404、5xx 或逾時，避免增加盤中資料陳舊時間。
- roots 與衍生合約的成功 LRU 各最多 16 項、TTL 60 秒，依 API base 與台灣日期分隔。pending 按鍵共用，不因成功快取容量中止有效讀者；依來源截止及最後讀者退出釋放。股票兩個原始來源仍分開快取與重試。
- 新增搜尋 metadata 專用四路 FIFO。每位讀者獨立取消，最後一人退出才中止底層；排隊取消或到期不再啟動。只限制未取消的有效 client 工作，不宣稱 daemon 或忽略 signal 的實體工作永遠不超過四筆。
- 部分來源失敗時保留其他可用結果；無結果且有來源錯誤時顯示可重試的搜尋失敗，不偽裝成找不到商品。
- 靜態指數精確命中立即回傳，直接代碼成功不等股票目錄。股票來源截止 1000 ms、其他單一來源 1200 ms，含排隊時間；逾時或無讀者時傳遞 AbortSignal 至 metadata HTTP，多階段不等於整次 1200 ms，客戶端中止也不等於 daemon 已停止內部作業。目錄提早失敗會釋放剩餘來源的本輪讀者。
- 股票 Base／名稱來源分開快取及重試，依服務與台灣日期失效；世代檢查阻擋 A→B→A 舊回應覆寫。typed 合約快取保留 code-only consumer 相容性，刷新失敗保留最後有效合約。
- 自選清單與命令面板啟用權證搜尋，傳遞商品型別並保留搜尋取得的完整合約。改輸入即撤掉舊建議；名稱搜尋待決時不允許 Enter 誤選舊商品。
- 兩個輸入入口處理 composition 狀態、isComposing、keyCode 229；換字、組字、關閉、選取或卸載會取消本輪。命令面板按型別、交易所、代碼保留明確鍵盤／滑鼠選取；未操作的預設面板不占住選取。補齊中仍可點選已備妥商品，舊提交與晚回不覆蓋新查詢。
- 權證在主視窗與彈出視窗的閃電下單、鋪單、整零價差面板均被阻擋，避免被誤當期貨。不增加新的權證交易功能。
- 修正 3 個既有測試的環境隔離：模擬全域 `fetch`，並清理觸發引擎測試的計時器。未修改服務管理或交易實作，也未弱化斷言。
- 修正測試入口：Vitest 只排除使用 Node test 的 ETF 產生器測試，`pnpm test` 依序執行兩套；任一失敗即整體失敗，既有 CI 呼叫不變。沒有刪除測試或僅用排除掩蓋失敗。

## 效能檢測與剩餘方案

前兩項已實作。效能驗收同時要求顯示正確、首批結果提早、完整結果不退化，以及減少可避免的請求。量測分成可控延遲、真實本機 metadata 與瀏覽器畫面，不將三者混為行情延遲。

| 檢測 | 修改前 | 本輪結果 |
| --- | --- | --- |
| 可控延遲案例 | 1020 ms 才回整份 | 20 ms 主商品、60 ms 期貨、1020 ms 完整清單，排序相同 |
| 真實 metadata 的台積名稱，client 冷快取 | 首次返回約 47.00 ms | 第一次 callback 16.63 ms、完整 45.18 ms |
| 3 次同時 `2330`，關聯結果已暖快取 | Base／Info 共 6 個 GET | 共 2 個 GET，少 4 個；完整結果相同 |
| 固定整輪查詢，含名稱、代號、ETF、台指 | 17 個 metadata GET | 13 個；沒有為 ETF 增加外部執行期查詢 |

實際 metadata 數字來自同一個隔離 sidecar 的單次前後對照，舊搜尋只在測試記憶體中載入，未修改 dev 或服務。僅重置 client 快取，daemon／作業系統快取未重置；不含 120／150 ms debounce、瀏覽器渲染或 SSE，不能推論延遲百分位或市場 SLA。完整清單時間並非每個案例都縮短，主要改善是提早可選與重複請求數。

目錄仍重建、正規化仍重算；先前合成 3155 筆 `searchStocks` 的 P95 為 0.75 ms，這部分暫不重寫。英數查無後的目錄備援亦維持原策略，避免無條件並行增加成功直查的流量。方法、對照與限制見 [效率驗收](../qa/product-search.md#搜尋效率複核)。
