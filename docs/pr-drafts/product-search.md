fix(search): 補齊櫃買指數名稱搜尋，整理商品目錄、相關排序與窄面板顯示

**Before:**

- 搜尋「櫃買」只會出現期貨，搜尋「櫃買指數」沒有結果，但直接輸入代號 `IX0043` 可以找到。
- 原因是名稱搜尋和代號搜尋走兩條不同的路徑。名稱搜尋查的是一份固定的指數名稱清單。這份清單沒有 `IX0043`，而且把所有指數都標成 TSE。代號搜尋則直接查券商合約。因此同一個商品，用名稱和用代號會得到不同結果。
- 我們接著檢查其他商品，又發現幾個同類問題：
  - 部分 ETF 名稱缺漏。
  - 同一檔股票用名稱或用代號搜尋，相關的現股、期貨、權證順序不一致。
  - 同系列 ETF 代號的排序不直覺。
  - 在窄面板與低高度面板中，結果列與選取項目不容易閱讀。
- 這些問題都和商品目錄及搜尋流程的結構有關。因此範圍從補一個指數名稱，擴大到商品目錄、搜尋流程與結果顯示。

**After:**

- 商品身分以券商目前有效的合約為準。名稱資料只補充名稱與別名，不會產生券商不支援的商品。指數仍不可下單。
- 補齊櫃買指數的名稱與別名，並改為逐筆標示交易所（`IX0043` 為 OTC）。現在用名稱或代號都能找到。
- 名稱與別名會在背景補充，來源是官方公開的 ETF，以及上市、上櫃、興櫃普通股的資料。不會每次按鍵都重新抓取。更新失敗時，保留上次有效的名稱。
- 搜尋「台積電」或 `2330`，會得到相同的相關商品與順序：現股 → 一般近月期貨 → 小型近月期貨 → 一般次月期貨 → 小型次月期貨 → 權證。其他查詢依輸入內容比對，結果不一定相同。
- 搜尋「台指」時，先列一般、小型、微型的近月，再列這三種規格的次月。
  - 期貨只列近月與次月，不包含所有遠月。
  - 券商不支援的規格會略過。
  - 連續月合約不會和對應的實際月份合約重複出現。
- 輸入 `00981` 時，`00981A`／`B`／`D`／`T` 會排在 `009810`、`009811` 前面。輸入完整的 `009810` 時，它仍排第一。字母後綴優先只是同系列代號的排序規則，不代表帶字母的都是主動式 ETF。
- 搜尋面板與自選清單共用單行結果列，代號在前、名稱在後。
  - 面板變窄時，先收起類別欄。選取的那一筆仍可看到完整資訊。
  - 類別顏色跟隨使用者自訂的主題。
  - 毛玻璃效果只套用在背景，文字維持不透明。
- 面板高度很低時，展開明細或調整面板大小後，原本選取的結果仍在可視範圍內，不必再按方向鍵。輸入框保持可見。明細區可以獨立捲動，也能用鍵盤安全操作。
- 內部把商品身分、名稱補充、相關排序與請求生命週期分開，減少重複運算、重複抓取，以及自選清單多餘的重繪。
  - 快速連續輸入會合併成一次查詢。
  - 輸入新查詢時，立即取消舊請求。
  - 舊回應不會覆蓋新結果。

效能：

命令搜尋的 p95 等待時間縮短約 14%～16%。
自選搜尋縮短約 28%～29%，完整商品排序一致。

**How:**

- 發布前已重跑本機測試、型別檢查與建置。瀏覽器結果採用同一份產品程式的最終驗收紀錄；不包含原生安裝包或正式部署。
- 測試結果：4244 項通過、0 項失敗、2 項既有原生測試略過。Node ETF 產生器測試 10 項通過。
- `tsc -b --force` 與 `vite build` 以 Node 直接執行並通過，`git diff --check` 也通過。
- 新增的請求測試涵蓋三種情況：連續輸入合併、立即取消舊請求、舊回應不覆蓋新結果。
- 在搜尋面板與自選清單兩個入口實際搜尋，確認以下結果：
  - 「櫃買」「櫃買指數」與 `IX0043` 都能找到櫃買指數。
  - `台積電` 與 `2330` 的相關排序一致。
  - 台指列出一般、小型、微型的近月與次月。
  - ETF 前綴查詢與完整代號查詢的排序正確。
- 窄面板以 320／360 px 寬度檢查，低高度面板以 240～359 px 高度檢查。確認單行顯示、沒有水平溢出、輸入框與選取列可見、明細可用鍵盤操作。
- 另外用 CSS reflow 模擬等效 200%／300% 縮放。這不是原生縮放。
- 驗證過程沒有送出委託，也沒有修改自選清單成員。
- 瀏覽器效能共 1200 次正式量測；比較基準、量測方式與請求取捨見 [完整驗收紀錄](https://github.com/Sinotrade/shioaji-pro-app/blob/codex/product-search-related/docs/qa/product-search-expanded-acceptance.md)。

已知限制：

- 原生版暫不啟用官方名稱的動態抓取，要等 cookie 隔離確認後才會開啟。券商名稱與內建名稱仍可搜尋。
- 正式網頁環境的名稱路由尚未在部署環境驗證。目前不能保證每個部署環境都會在背景更新名稱。
