# 非同步資料狀態設計規範

交易終端的每個資料區塊由**該資料的查詢狀態**決定畫面，不以「目前陣列長度是 0」推斷已查詢完成。共用的呈現元件是
[`AsyncStatus`](../../src/components/async-status.tsx)；動畫沿用
[`Orb`](../../src/components/orb.tsx) 的 `radial` 變體。元件只負責顯示，
資料擁有者仍須提供真實的 phase。

| 狀態 | 畫面 | 判定 |
| --- | --- | --- |
| 首次讀取／切換資料來源 | `loading`：Orb＋具體動詞與對象，例如「載入持倉…」 | 尚無**成功確認**的此來源結果，而且讀取仍在等待；立即顯示，不加固定延遲 |
| 有部分結果，其他請求未結束 | 保留可用資料，旁邊小型 `loading`（「載入其餘商品…」） | 不拿全清單的最慢項阻擋第一筆商品；未完成時避免覆寫完整伺服器清單 |
| 背景更新，已有可信資料 | 保留舊資料，更新按鈕／局部列顯示活動狀態 | 不清空整個面板、不顯示全版遮罩；需要時標示資料時間 |
| 已確認成功，結果為空 | `empty`：清楚說明空清單或目前篩選無結果，**不顯示 Orb** | 所有必要帳戶／分頁讀取成功後才能宣告「無持倉／無委託」 |
| 讀取失敗，沒有可信結果 | `error`：說明資料尚未取得，提供現有重試入口，**不顯示 Orb** | 不以 0、空清單或無資料取代失敗；多帳號任一必要讀取失敗時也不可宣告整體為空 |
| 尚未選擇商品／無需查詢 | `idle`：提示使用者選擇，不顯示 Orb | 不用無限動畫暗示後台仍在工作 |

## 視覺與無障礙

- 全 App 一般載入使用 `AsyncStatus phase="loading"`。預設為 12px `radial` Orb＋文字；面板中央可用 14px，行內 10–12px。伺服器連線、開機等已有方向語意的特殊狀態可沿用 `ring` 或 `sweep`。
- 文字要點名等待對象；避免只有動畫、籠統「載入中」，也避免捏造百分比或預估時間。
- Loading 訊息帶 `role="status"`；錯誤帶 `role="alert"`。Orb 自身 `aria-hidden`。系統啟用 reduced motion 時，點陣停在靜態相位，文字仍完整可讀。
- 活動狀態不可遮擋風控、重試或已載入資料；不會因為某個不相關的查詢而出現在釘選商品面板。動畫停止條件必須由同一筆查詢的成功／失敗驅動。

## 套用位置與檢查

- 自選清單：未有任何商品時「載入清單…」；第一筆可用後立即顯示，未完成時「載入其餘商品…」；錯誤與真正空清單分開。
- 連動商品面板：跟自選清單的首筆商品；釘選面板跟自己的商品查詢。兩者不得互相借用 loading flag。
- 持倉／委託：首輪查詢未結束前不能顯示 `[0]` 或「無持倉／無委託」；部分帳戶失敗或失去連線時提示尚未取得，保留已知資料與風控限制。
- K 線、走勢、歷史成交、分價量、商品目錄、權證、選擇權、組合商品、排行、帳務、帳號設定與商品搜尋：沿用同一 `AsyncStatus` 外觀，依各自的請求顯示 loading／empty／error；刷新時保留可用資料。歷史讀取失敗不能說「今日無成交」；即時資料開始流入時可繼續顯示已取得的資料。

實測時至少覆蓋「慢回應、成功空結果、失敗、多帳號部分失敗、切換資料來源」；單元測試、合成 CI 與原生 WebView QA 分別記錄，不互相替代。
