# ADR 0001: index_components 建底查詢紀律

日期:2026-08-27
狀態:已採納

## 背景

shioaji 1.7.4 的 `index_components` 提供權威查詢與 projection 串流雙軌。查詢有每日資料額度(429=額度用盡),官方文件禁止連續輪詢;串流事件為各投影的整包替換,無增量、無回放。市場脈動與產業全景面板遷移到此資料源時,必須決定查詢與串流的責任邊界。

## 決策

查詢(建底)只允許兩個時機:

1. 該指數在本 session 尚無本地狀態(首次有面板取用)。
2. 日切:串流事件攜帶的交易日 ≠ 本地狀態的交易日(資料驅動偵測,不依賴牆上時鐘 — 與現貨當日走勢的 session 判定同一哲學)。

明確禁止:

- SSE 斷線重連後重查 —— 排行/群組事件是整包替換,串流自癒;只要本地已有建底,重連不查。
- 面板 remount 重查 —— store 為 session 級,面板共用。
- 任何定時輪詢或把查詢當畫面刷新。
- 429(日額度用盡)後的重試或繞路 —— 降級顯示,不自動補救。503(state_not_ready)為暖機狀態,允許退避重試。

建底 snapshot 依官方「查詢→串流投影映射」在 client 端投影成各訂閱投影的初始態,不得從價格重算指標;串流事件與建底以 `calculated_at` 新者勝。

## 後果

- 收盤/盤後時段串流僅剩 heartbeat,面板內容完全依賴當日建底;建底 429 失敗時盤後面板為空(顯示額度用盡),此為接受的降級。
- 下鑽層設計被此紀律約束為純串流形態(主力 10 檔+餘量),不做依賴全量建底+報價批掛的完整成員牆。
- 未來新增以 index_components 為底的面板,一律接同一 store,不得自行查詢。
